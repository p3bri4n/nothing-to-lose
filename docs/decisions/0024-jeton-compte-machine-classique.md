# 0024 — Jeton du compte machine : jeton classique à portée `repo`

- **Date** : 2026-11-07
- **Statut** : décidée (précisée par [0027](0027-portee-workflow-jamais.md) : jamais la portée `workflow`)
- **Contexte** : la décision [0021](0021-fusion-compte-machine-agents.md) prévoyait, pour le compte machine des agents, un jeton à granularité fine (*Contents*, *Pull requests* et *Issues* en écriture, limité au dépôt). La [recherche du 2026-11-07](../recherches/2026-11-07-garde-fous-git-gh.md) (section 5) établit, avec une confiance élevée, que la documentation GitHub lue ce jour-là exclut le jeton à granularité fine pour contribuer à un dépôt dont l'utilisateur n'est que collaborateur (limite déjà signalée dans le changelog du 2025-03-18, non levée en 2025-2026 à la connaissance de la recherche). Le dépôt étant personnel, le compte machine ne peut donc pas recevoir de jeton à granularité fine capable d'y écrire.
- **Options présentées** :
  1. Jeton classique, portée `repo` (`workflow` seulement si les agents modifient `.github/workflows/`), durée courte, compte machine sans aucun autre accès. Avantages : aucune dépendance nouvelle, procédure simple, fonctionne sur ce dépôt. Inconvénients : la portée `repo` est un plafond sur tous les dépôts accessibles au compte, pas un filtre ; pas de restriction fine (*Actions*, *Workflows*) ; la sécurité repose sur l'isolement du compte.
  2. GitHub App installée sur ce seul dépôt : jeton d'installation restreint à ce dépôt, valable une heure, requêtes attribuées au bot (permissions *Contents* et *Pull requests* en écriture). Avantages : périmètre par dépôt, expiration rapide. Inconvénients : plus lourd (création et installation de l'application, renouvellement du jeton par un script), nouvelle dépendance ; effet des contournements et des approbations sur une application non vérifié.
  3. Dépôt passé dans une organisation, compte machine membre avec le rôle *Write*. Avantage : la limite visant les collaborateurs externes ne s'appliquerait plus (inférence, non testée). Inconvénient : invasif (changement de propriétaire du dépôt, adaptation de la configuration Terraform et des URL), hors de proportion pour ce besoin.
- **Recommandation des agents** : option 1 (jeton classique à portée `repo`), recommandation de la session principale.
- **Décision de l'utilisateur** : option 1.
  - le jeton du compte machine est un **jeton classique à portée `repo`**, sans la portée `workflow` (jamais, [0027](0027-portee-workflow-jamais.md)) ;
  - durée courte (30 jours, renouvellement par la procédure de `compte-machine-agents.md`) ;
  - le compte machine n'a aucun autre accès (aucun autre dépôt, aucune organisation) et ne sert à rien d'autre.
- **Conséquences** :
  - précise [0021](0021-fusion-compte-machine-agents.md) : le jeton n'est pas à granularité fine mais classique. Le reste de 0021 est inchangé (compte en rôle *Write*, une approbation requise, fusion réservée à l'utilisateur, jeton jamais rattaché au compte propriétaire) ;
  - la portée `repo` est un **plafond** sur tous les dépôts accessibles au compte machine. Le compte ne doit donc être invité sur aucun autre dépôt ni rattaché à aucune organisation, et ne doit servir à rien d'autre que les agents de ce dépôt ;
  - la règle « jamais *Actions* en écriture » ne s'applique plus au jeton lui-même, les jetons classiques n'ayant pas cette granularité. `gpu-eval.yml` reste protégé par sa garde `github.repository_owner == github.actor` et, selon l'inférence de la recherche (non testée), par le fait que le rôle *Write* ne permet pas de gérer les paramètres du dépôt ;
  - une pull request approuvée est fusionnable par **tout compte *Write*** : l'utilisateur ne doit pas approuver une pull request d'agent sans la fusionner dans la foulée (fusion par contournement sans approbation, ou approbation immédiatement suivie de la fusion) ;
  - à revoir avec une GitHub App si les agents tournent un jour sans surveillance (sandbox, reporté après PP par [0015](0015-sandbox-reporte-apres-pp.md)) ;
  - la documentation (`docs/technique/compte-machine-agents.md`, `circuit-git.md`, `garde-fous-bash.md`, `ci-cd.md`, `docs/plans/PP.md`) est alignée sur ce choix.
